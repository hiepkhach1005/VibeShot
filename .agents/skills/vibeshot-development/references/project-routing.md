# VibeShot documentation routing

Read only what the task needs:

- Product behavior or scope: `docs/PRODUCT_SPEC.md`
- Component ownership and data flow: `docs/PROJECT_MAP.md`
- Technical design and invariants: `docs/ARCHITECTURE.md`
- Milestones and ordered implementation: `docs/IMPLEMENTATION_PLAN.md`
- Coding and review constraints: `docs/ENGINEERING_RULES.md`
- Plan/code/test workflow: `docs/PROCESS.md`
- Test cases and quality gates: `docs/TESTING.md`
- Decisions and product history: `docs/HISTORY.md`
- Current status and next task: `docs/PROGRESS.md`
- Research evidence: `docs/SOURCES.md`
- Repeatable task prompts: `prompts/`

If implementation reveals that a document is wrong, update the owning document in the same change.
Do not duplicate the same requirement across multiple documents unless one location is a short link.
